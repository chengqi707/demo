# 贪吃蛇游戏 PRD（产品需求文档）

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 产品名称 | 贪吃蛇（Snake） |
| 文档版本 | v1.3 |
| 文档状态 | 草稿 |
| 目标平台 | Web 浏览器（桌面端优先，兼容移动端） |

## 2. 项目背景与目标

贪吃蛇是经典的休闲小游戏，规则简单、上手门槛低。本项目旨在实现一个可在浏览器中直接运行的贪吃蛇游戏，作为演示项目（demo）验证完整的「需求 → 开发 → 交付」流程。

**目标：**

- 提供完整可玩的贪吃蛇核心玩法
- 代码结构清晰，便于后续扩展（关卡、皮肤、排行榜等）
- 无需安装，打开页面即可游玩

### 2.1 非目标（Out of Scope）

本期明确不做以下事项，避免范围蔓延：

- **商业化**：不接入广告（激励视频 / 插屏）、不做内购、不做付费皮肤
- **账号与后端**：不做账号体系、云同步与在线排行榜（最高分仅本地 localStorage）
- **重度内容扩展**：不做多关卡、剧情模式、联网对战

说明：本项目定位是验证「需求 → 开发 → 交付」流程的 demo。若未来考虑商业化（广告变现 / 皮肤内购 / 流量导流 / 品牌定制），需引入后端与 SDK，属于另起阶段评估的事项，本期架构不为此预留接口。

## 3. 目标用户

- 休闲玩家：利用碎片时间进行轻量娱乐
- 学习者：通过本项目了解小游戏的基本实现思路

## 4. 核心玩法

- 玩家控制一条蛇在固定大小的网格场地中移动
- 场地中随机出现食物，蛇吃到食物后身体增长一节，同时得分增加
- 场地中会随机刷新**特殊道具**（双倍得分、减速时钟、护身护盾、瘦身果实），吃到后获得对应的限时增益效果，增加策略性与爽感
- 蛇头撞到场地边界或自己的身体时，游戏结束（护盾生效期间撞墙可穿越，见 5.4）
- 随着得分提升，蛇的移动速度逐渐加快，难度递增

## 5. 功能需求

| F-06 | 计分 | 每吃一个食物得 10 分，实时显示当前得分 |

### 5.4 特殊道具明细（F-14）

道具每隔一段时间（建议每 15～25 秒）在场地空闲格子随机刷新一个，场上最多同时存在 1 个；若 10 秒内未被吃到则消失。道具不使身体增长。

| 道具 | 视觉标识 | 效果 | 持续时间 |
| --- | --- | --- | --- |
| ⭐ 双倍得分 | 金色五角星 | 得分获取 ×2（每个食物 20 分） | 10 秒 |
| 🕐 减速时钟 | 蓝色时钟 | 移动间隔重置为初始值（难度回落），之后仍随得分递增 | 立即生效 |
| 🛡️ 护身护盾 | 青色盾牌 | 撞墙不死：从对面边界穿出继续移动；撞到自身仍判负 | 8 秒 |
| ✂️ 瘦身果实 | 紫色剪刀 | 身体立即缩短 2 节（保底保留 3 节），得分不受影响 | 立即生效 |

- 效果生效期间界面上需有明确提示（如道具图标 + 剩余秒数）
- 同类道具效果不可叠加，重复吃到时刷新持续时间

## 6. 非功能需求

- **性能**：游戏循环稳定，帧率流畅（≥ 30 FPS），操作延迟不可感知
- **兼容性**：支持 Chrome / Edge / Firefox / Safari 主流浏览器最新两个大版本
- **体积**：纯前端实现，无后端依赖，资源体积小、加载快
- **可维护性**：游戏逻辑与渲染分离，核心参数（场地大小、初始速度、分值）可配置

## 7. 技术方案选型与架构

### 7.1 技术选型

| 项目 | 选型 | 理由 |
| --- | --- | --- |
| 语言 | 原生 HTML + CSS + JavaScript（ES6+） | 零依赖、免构建，打开即用，符合 demo 项目「验证流程」的定位 |
| 渲染 | Canvas 2D API | 网格类游戏需要高频重绘，Canvas 相比 DOM 操作性能更好、像素控制更精确 |
| 游戏循环 | `setInterval` 固定步长（而非 requestAnimationFrame） | 贪吃蛇是离散节拍驱动的回合式移动，固定间隔天然契合「速度递增 = 缩短间隔」的难度模型，逻辑更简单可控 |
| 状态持久化 | localStorage | 仅需持久化最高分一项数据，本地存储即可满足，无需后端与账号体系 |
| 样式管理 | CSS 自定义属性（:root 变量）集中管理配色 | 为 P2 的皮肤 / 主题扩展预留能力，换肤即换变量 |
| 输入方案 | 键盘（方向键 / WASD / 空格）+ 触屏滑动 + 虚拟方向键 | 桌面与移动端双通道输入；通过 `@media (pointer: coarse)` 自动切换展示虚拟按键 |
| 部署 | 静态托管（GitHub Pages） | 单文件纯静态产物，无服务器成本，push 即发布 |

### 7.2 架构设计

采用单文件架构（`index.html`），脚本以 IIFE 包裹避免污染全局作用域，内部按职责分层：

- **配置层**：`GRID`、`CELL`、`BASE_INTERVAL`、`MIN_INTERVAL`、`SPEED_STEP`、`SCORE_PER_FOOD` 等核心参数集中定义为常量，可调可配
- **状态层**：`snake`、`dir`、`pendingDir`、`food`、`score`、`best` 等游戏状态变量集中管理
- **逻辑层**：`step()` 单步推进（移动 → 碰撞判定 → 吃食生长 → 加速）、`placeFood()` 空闲格随机生成食物、`endGame()` 结算
- **渲染层**：`draw()` 每步全量重绘画布（背景 → 网格 → 食物 → 蛇），渲染只读状态、不修改状态
- **输入层**：键盘 / 触摸滑动 / 虚拟按钮三路输入统一汇入 `setDir()`，在此拦截 180° 反向
- **界面层**：overlay 遮罩组件复用开始 / 暂停 / 结束三种界面，通过 `hidden` 类切换

**关键设计决策：**

1. **状态机驱动**：游戏处于 `ready → running ⇄ paused → gameOver` 四种状态之一，`running` / `paused` / `gameOver` 标志位约束输入与循环的行为边界
2. **方向缓冲（pendingDir）**：玩家输入不立即生效，而是缓存到下一拍移动时应用，避免一拍内连续按键导致的「原地掉头自杀」
3. **数据与渲染分离**：逻辑层只操作坐标数据，渲染层只读取状态绘制，后续扩展障碍物、皮肤时互不影响
4. **速度模型**：`interval = max(MIN_INTERVAL, BASE_INTERVAL - 食物数 × SPEED_STEP)`，线性加速且封顶，保证难度曲线平滑
5. **道具系统可插拔**：道具抽象为「类型 + 生成计时 + 生效计时」三要素，生成复用 `placeFood()` 的空闲格随机逻辑，效果以 `{ type, expiresAt }` 挂在状态层，`step()` 中按类型分支结算——新增道具只需加配置与分支，不动核心循环

## 8. 界面与交互

- **主界面**：游戏场地（约 20×20 网格）、当前得分、最高分
- **道具提示**：道具生效期间，计分栏旁展示对应图标与剩余秒数
- **开始页 / 遮罩**：游戏名称 + 开始按钮 + 操作说明（含道具图例简介）
- **结束页 / 遮罩**：本局得分、最高分、重新开始按钮
- **视觉风格**：简洁扁平，蛇、食物、道具、背景四者对比清晰，道具配色与普通食物明显区分

## 9. 验收标准

1. 打开页面即可开始游戏，核心循环（移动 → 吃食 → 生长 → 加速）完整可用
2. 撞墙、撞自身均能正确触发游戏结束并可重新开始
3. 计分准确，最高分在刷新页面后仍然保留
4. 反向操作被正确拦截，不会出现「原地掉头自杀」
5. 道具按规则刷新与消失；双倍得分、护盾、减速、瘦身四种效果均正确生效与到期结束，护盾期间撞墙穿越、撞自身仍判负
6. 在桌面端主流浏览器与移动端浏览器上均可正常运行
